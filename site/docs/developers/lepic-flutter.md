# lepic-flutter

lepic-flutter is the Dart package `lepic`: the Flutter binding of [LEPIC](lepic.md). Its Dart half
is generated by flutter_rust_bridge from LEPIC's `crates/lepic-ffi`. A build hook bundles the
prebuilt native library into the app, so the app needs no Rust toolchain.

Source: [github.com/BTLabsUK/lepic-flutter](https://github.com/BTLabsUK/lepic-flutter), licence
Apache-2.0. The package is not on pub.dev; an app installs it from git. Its repository has a
[usage guide](https://github.com/BTLabsUK/lepic-flutter/blob/main/doc/guide.md) with every call.

```yaml
dependencies:
  lepic:
    git:
      url: https://github.com/BTLabsUK/lepic-flutter.git
```

The package needs Dart `^3.13.0` and Flutter `>=3.47.0`; `pubspec.yaml` holds the exact
constraints.

## What is in the repository

| Path | Holds |
|---|---|
| `lepic.rev` | The LEPIC commit the package is generated from and built against |
| `lib/lepic.dart` | The public Dart API; `lib/src/rust/` is the generated half and is never edited by hand |
| `lib/testing.dart` | Test helpers (`MockChain`, `MockRelay`, `MockStockPeer`), for tests only |
| `hook/build.dart` | The build hook that bundles the native library into an app |
| `tool/lepic.sh` | `sync`, `build`, `test`, `emulator-test`, `generate`, `check` and `lib` against the pinned LEPIC |
| `tool/generate.dart` | The codegen configuration, and the patch applied after it |
| `test/`, `emulator_test/` | Host tests, and an Android device test app with no UI |

The Rust half of the bridge, `frb_generated.rs`, lives in LEPIC's `crates/lepic-ffi`. Both halves
come from one codegen run, and three checks keep them together:

- In LEPIC, `cargo xtask repo-lint` compares `crates/lepic-ffi/src/api` and `frb_generated.rs` with
  the hash in `bridge.sha256`, which the codegen run writes.
- In this repository, `tool/lepic.sh check` runs the codegen at the pin and fails unless the result
  equals both the committed Dart half and the pinned LEPIC's Rust half.
- At run time, `RustLib.init` refuses a library generated from another API.

The version of flutter_rust_bridge must agree in `pubspec.yaml`, LEPIC's `Cargo.lock` and the
codegen; `tool/lepic.sh` checks all three. The decision is
[ADR 0023](https://github.com/BTLabsUK/lepic/blob/main/docs/adr/0023-binding-in-its-own-repository.md).

## Using the package

An app creates one `LepicRuntime`, gives each wallet a `SecretStore` adapter over its secure
storage, and calls `EpicWallet`. Calls return Futures and Streams, and every failure is a thrown
`WalletError`.

```dart
import 'package:lepic/lepic.dart';

await RustLib.init();
final runtime = LepicRuntime(logLevel: LogLevel.info);
final store = lepicSecretStore(mySecureStorageAdapter); // implements SecretStore
final wallet = await EpicWallet.create(
  runtime: runtime,
  config: WalletConfig(
    dataDir: dir.path,
    chain: Chain.mainnet,
    nodeUrl: 'https://node.example:3413',
    epicboxDomain: 'relay.example.org',
    epicboxPort: 443,
    onionRoutes: const [],
    tuning: tuning, // timeouts, retries and limits, from the app's settings
    offline: false,
    torWanted: false,
  ),
  store: store,
  password: password,
);
```

`WalletConfig` carries the node and relay, the network, the onion routes, the timeouts and limits
(`NetTuning`, no defaults), `offline` for a cold wallet, `torWanted`, the feature bits and profile
the app claims to paired contacts, an optional `domain`, and a `HostPolicy`. `HostPolicy` and
`PinSettings` (passed to `LepicRuntime.withPinSettings`) hold the limits and presets that belong to
the app. Every field is optional and an empty one takes the default
([ADR 0036](https://github.com/BTLabsUK/lepic/blob/main/docs/adr/0036-policy-values-are-host-parameters.md)).

How the host unlocks a wallet:

- **Password.** `create`, `open` and `mnemonic` take the wallet password. The seed is stored as a
  vault under `lepic.vault`.
- **PIN.** `createWithPin` and `openWithPin` generate the wallet password, seal it under the PIN
  with a random key stored as `lepic.pin-key`, and return the sealed text for the app to store.
  A PIN has at least 6 characters by default (`PinSettings.minLen`). The first 3 wrong attempts
  wait for nothing; later ones wait 30 seconds, doubling up to an hour. The count is kept as
  `lepic.pin-failures`.
- **Restore.** `create` with a `mnemonic` restores a wallet, and `scan` then runs to the end
  before the wallet can receive or make change. `restoreFromHeight` starts that scan at a block
  height ([ADR 0035](https://github.com/BTLabsUK/lepic/blob/main/docs/adr/0035-restore-from-a-start-height.md)).
  `importWalletSeed` restores from the text of an `epic-wallet` `wallet.seed`.
- **One directory, one runtime.** A data directory is open in one runtime at a time, across
  processes too; LEPIC holds an OS lock on `.lepic.lock` in it. `EpicWallet.lock()` locks a wallet
  at once and ends the calls in progress with `cancelled`.

Use one `SecretStore` per wallet. The keys have fixed names, so two wallets in one store share one
vault slot.

## Secrets at the boundary

[ADR 0014](https://github.com/BTLabsUK/lepic/blob/main/docs/adr/0014-secrets-at-the-flutter-boundary.md)
decides what may cross between Dart and Rust.

| Direction | Value |
|---|---|
| Dart to Rust | The wallet password, PIN, recovery phrase and `wallet.seed` password the user types; the node API secret the user configures; a pairing link or words the user types or scans |
| Rust to the `SecretStore` and back | The vault (`lepic.vault`, `lepic.vault-next` during a password change) and, for PIN wallets, the PIN key (`lepic.pin-key`, `lepic.pin-key-pending` during a PIN change) |
| Rust to Dart | The recovery phrase, after the password or PIN is checked; a pairing invite link and its five pairing words |
| Never | Seed bytes, private keys, blinding factors, nonces, vault keys, the wallet password generated for a PIN wallet, the root secret |

Every secret crosses as a Dart `String`. Rust wipes the copies it holds, but the Dart string and
the bridge buffer that carries it stay in memory until reused. An app holds them only as long as a
call needs them. The sealed PIN text and the vault are not secret alone; whoever holds both the
sealed text and the store contents can try PINs offline, slowed by Argon2id. The store belongs on
the device, backed by the platform keystore and excluded from backups.

## Errors

`WalletError.kind` is a `WalletErrorKind` and `WalletError.code` is its number. Codes keep their
meaning. `message` is English text for logs and holds no secret. The kinds and numbers are in
`crates/lepic-ffi/src/api/error.rs` and in LEPIC's
[FFI page](https://github.com/BTLabsUK/lepic/blob/main/docs/ffi.md). A panic inside LEPIC arrives as
kind `panic`, and the runtime stays usable. Stream calls report a failure as the stream's error.

## Native libraries

`hook/build.dart` adds the prebuilt `liblepic_ffi` for the target as a Flutter native asset. The
library keeps the name stem `lepic_ffi`, so the generated `RustLib.init()` loads it.

| Target | File in `native/<rust triple>/` | Built on |
|---|---|---|
| Android arm64-v8a, armeabi-v7a, x86_64 | `liblepic_ffi.so` | Linux or macOS with the Android NDK and `cargo-ndk` |
| iOS device and simulator, arm64 | `liblepic_ffi.dylib` | macOS with Xcode |
| Linux x86_64 | `liblepic_ffi.so` | Linux x86_64 |
| Windows x86_64 | `lepic_ffi.dll` | Windows with Visual Studio Build Tools (C++) |

macOS builds get no bundled library. Static link mode is rejected. The libraries link against
Android API 24, and the hook fails for an app with a lower `minSdk`.

`tool/lepic.sh` builds them from the LEPIC commit in `lepic.rev`:

```bash
tool/lepic.sh sync                     # clone LEPIC at the pin into third_party/lepic
tool/lepic.sh build all                # every target this host can build
tool/lepic.sh build linux android      # or windows, or Rust target triples
```

`LEPIC_DIR` names an existing LEPIC checkout instead of `third_party/lepic`; it must be clean and
at the pin. `LEPIC_REPO` is the source `sync` clones from. Each `build` runs
`cargo xtask mobile --package --out native` in LEPIC. See
[Build from source](build/index.md).

Each library directory also holds three files:

| File | Holds |
|---|---|
| `SHA256SUMS` | The SHA-256 of each library |
| `FEATURES` | The `lepic-ffi` features the library has, such as `tor` |
| `SOURCE` | The LEPIC commit, whether the tree was clean or modified, and the rustc version |

The hook refuses a library whose hash is not in `SHA256SUMS`, one without `SOURCE`, one built from
another commit than `lepic.rev`, and one built from a modified tree. `SHA256SUMS` catches truncated
or mixed-up files; it is not a signature.

Libraries are built with Tor. `WFE_TOR=0` (also `false` or `off`) builds them without it
(`cargo xtask mobile --package --no-tor`, ADR 0026). The Dart API is the same: `startTor` and the
other Tor calls fail with `unsupported`, and `torStatus` is `off`. Two user defines in the app's
`pubspec.yaml` steer the hook:

```yaml
hooks:
  user_defines:
    lepic:
      native_dir: ../lepic-native # holds <rust triple>/liblepic_ffi.*
      tor: false # only a library built without Tor; true: only one with Tor
```

A relative `native_dir` resolves against the app's `pubspec.yaml`. Without `tor`, the hook bundles
either kind.

## Tests

Tests run on x86_64 Linux from the package root:

```bash
tool/lepic.sh test                  # flutter test arguments may follow
tool/lepic.sh emulator-test         # the device test app, on an attached Android device
tool/lepic.sh generate              # both bridge halves, after changing crates/lepic-ffi/src/api
tool/lepic.sh check                 # fail on drift
```

`test` builds `lepic-ffi` with the `mock` feature (a scripted node and relay) into `test_native/`,
which the package's `pubspec.yaml` names as `native_dir`, and runs `flutter test`. The tests read
LEPIC's golden vectors from the same checkout. `MockChain` and `MockRelay` work only in a `mock`
build and fail with `unsupported` in any other. `emulator-test` builds the mock library for the
device's ABI and runs create, restore, file send, receive and finalize against `MockChain`.

`generate` writes the Dart half to `lib/src/rust/` and, in the LEPIC checkout, `frb_generated.rs`
and `bridge.sha256`. Commit those two in LEPIC, move `lepic.rev` to that commit, and run
`tool/lepic.sh check`.

LEPIC's `interop/` stack, a Docker private network with a reference node, an Epicbox relay and an
`epic-wallet` funder, serves tests against a local chain; see [Testing](testing.md).
